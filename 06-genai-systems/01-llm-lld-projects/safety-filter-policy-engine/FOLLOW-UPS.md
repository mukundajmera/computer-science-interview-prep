# Safety Filter & Policy Engine - Follow-Up Questions

## Follow-up questions
1. How would you implement early termination / short-circuiting so we don't evaluate expensive ML filters if a simple regex already blocks the content?
2. How would you handle stateful filters (e.g., tracking user behavior over multiple turns to detect harassment)?
3. How do you manage rule collisions, overrides, or precedence when merging policies from multiple `PolicySet` instances?
4. How would you design a hot-reload mechanism to update policies in a running engine without restarting or dropping concurrent requests?
5. How would you handle multi-modal content, like images or audio, within the same safety filter architecture?

## Variants and extensions
1. **Confidence-Aware Triage:** Extend the engine to handle fuzzy ML models with confidence scores, routing marginal cases to human review queues (v2-extended track).
2. **Context-Aware Safety:** Adjust rules based on user history, persona, or application context rather than evaluating text in complete isolation.
3. **Redaction and Masking:** Instead of just returning ALLOW/FLAG/BLOCK decisions, extend the system to return modified strings with sensitive information masked or replaced.
4. **Streaming Evaluation:** Evaluate chunks of streaming text as they are generated by an LLM to intercept and block toxic output mid-generation.

## Interviewer probes to prepare
- "Why use the Chain of Responsibility pattern for the filter pipeline? What are its trade-offs here?"
- "How does the Strategy pattern for content filters make testing and extension easier?"
- "What happens to the time complexity as the number of regex patterns scales to thousands? How could you optimize it (e.g., using Aho-Corasick instead of multiple regexes)?"
- "Why are decisions ordered statically (BLOCK > FLAG > ALLOW), and what are the limitations of this strict precedence?"
