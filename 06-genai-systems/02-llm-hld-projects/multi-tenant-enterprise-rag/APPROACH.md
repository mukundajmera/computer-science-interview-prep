# Approach: Multi-Tenant Enterprise RAG

## Key Focus Areas

1.  **Strict ACLs:** Enterprise search fails if permissions are leaked. The architecture must place ACL filtering directly inside the retrieval engine (pre-filtering / single-stage filtering) rather than post-filtering. Post-filtering leads to massive recall cliffs.
2.  **Hybrid Retrieval & RRF Interfaces:** BM25 handles exact keyword matches (e.g., error codes, specific part numbers) better than dense embeddings. Both vector and keyword retrieval interfaces return standardized schema (`chunk_id`, `score`, `tenant_id`, `acl_list`). RRF then aggregates the disparate scores into a unified rank before reranking. RRF guarantees top-k deterministic ordering from the combined lists.
3.  **Latency:** The sub-500ms SLA means reranking cannot evaluate thousands of documents. We must retrieve ~100 docs per path, RRF them, and cross-encode only the top 20-30.

4.  **Ingestion/Chunk ACL Inheritance:** During CDC ingestion, chunk boundaries must perfectly inherit their parent document's ACL metadata and tenant ID. It's not enough to attach ACLs at the document level; each individual vector/chunk in the datastore must carry the exact ACL state to enforce pre-retrieval filtering.

5.  **Revocation & Trust Boundaries:**
    *   **Revocation Boundary:** When a user is removed from a group or a document's permissions change, CDC must immediately emit a tombstone/update to the vector store to update the `acl_list` for every corresponding chunk. This guarantees revocation is propagated per stage. Until this asynchronous update propagates, there is a revocation delay where stale access may occur.
    *   **Cache Trust Boundary:** Any query or embedding cache must be keyed by `(tenant_id, user_id, query_hash)` to prevent cross-tenant or cross-user data leakage. A shared `tenant_id` cache is dangerous if users have heterogeneous RBAC profiles.
    *   **Citation Trust Boundary:** The LLM prompt and output generation phase must strictly only receive chunks that passed the retrieval ACL filter. Citations generated by the LLM are inherently trusted only if the input context window was securely populated. The application layer must verify that all cited `chunk_ids` in the LLM's response were part of the initially provided, ACL-filtered context.
