### Deep Dive: Query Decomposition

When architecting the query decomposition module, engineers must consider multiple factors. User queries in AI search are often complex and multi-faceted. The query decomposition module breaks these down into simpler, atomic sub-queries that can be executed independently against the search index. This is not a trivial task. In a high-throughput environment, Decomposition must handle temporal constraints. 'Who won the World Series last year?' needs entity resolution for 'last year' based on the current timestamp. Failure to optimize this leads to unacceptable TTFT.

Another critical aspect of query decomposition involves state management and failover. A critical trade-off is latency vs. recall. More sub-queries mean better recall but higher retrieval latency and more tokens sent to the final generation model. For instance, if the primary cluster degrades, the system must gracefully fallback. To mitigate latency, sub-queries are executed concurrently in a scatter-gather pattern.
