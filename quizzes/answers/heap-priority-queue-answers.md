# Heap / Priority Queue Quiz Answers

| Question | Answer | Why correct | Why an alternative fails |
|---:|---|---|---|
| 1 | **A** - It exposes the current minimum or maximum while supporting updates efficiently | Proof and Invariant: A heap efficiently maintains the running maximum or minimum (the priority boundary) in O(log n) time per update without sorting the entire array. | Distractor Failure: Choosing B fails because a heap does not keep all elements fully sorted; it only maintains a partial ordering based on the parent-child heap property. |
| 2 | **B** - Find the kth largest value in a stream | Proof and Invariant: Finding the kth largest element dynamically requires maintaining a bounded frontier (size-k min-heap) to filter out smaller elements as they arrive. | Distractor Failure: Choosing C fails because directed cycles are detected using graph traversal algorithms like DFS with visit states, not a size-bound heap. |
| 3 | **B** - Build a frequency map | Proof and Invariant: Heap priority depends on element frequencies, so you must first aggregate exact counts (e.g., via hash map) before any top-k selection can occur. | Distractor Failure: Choosing A fails because reversing the input does not produce counts, which are fundamentally required for top frequent calculations. |
| 4 | **A** - Min-heap | Proof and Invariant: A min-heap of size k retains the k largest elements seen so far; its root is the smallest of these k, which is precisely the kth largest overall. | Distractor Failure: Choosing B fails (if it were max-heap) because a max-heap of size k would evict the largest elements, leaving you with the k smallest instead. |
| 5 | **A** - Find Median from Data Stream | Proof and Invariant: The streaming median inherently requires tracking both the largest of the lower half (max-heap) and the smallest of the upper half (min-heap). | Distractor Failure: Choosing B fails because LRU cache uses a hash map and doubly-linked list for access recency, not two heaps for magnitude halves. |
| 6 | **B** - Merge K Sorted Lists | Proof and Invariant: To merge k sorted lists, the heap stores exactly one active candidate (the current head) from each list, ensuring O(log k) selection of the next global minimum. | Distractor Failure: Choosing A fails because pushing all elements at once defeats the purpose of the k-way merge; it takes O(N) space instead of O(k) and ignores the sorted inputs. |
| 7 | **A** - Task Scheduler with cooldown | Proof and Invariant: Scheduling with cooldown requires separating tasks that are currently available (priority queue by frequency) from those waiting for cooldown release (often a standard queue). | Distractor Failure: Choosing B fails because a single stack cannot enforce time-based cooldown releases or frequency-based priorities. |
| 8 | **A** - K Closest Points | Proof and Invariant: The closest points are selected by evaluating their Euclidean distance from the origin and maintaining the k closest points dynamically. | Distractor Failure: Choosing B fails because sorting by x-coordinate alone ignores the y-coordinate contribution to the actual geometric distance. |
| 9 | **A** - The kth largest value | Proof and Invariant: In a min-heap tracking the top-k values, the root represents the minimum of the k largest elements seen, thus serving as the kth largest eviction boundary. | Distractor Failure: Choosing C fails because the root is explicitly the smallest of the kept values, not the absolute largest value in the entire stream. |
| 10 | **D** - The least frequent candidate among the kept top-k values | Proof and Invariant: When tracking top-k frequencies with a min-heap, the root holds the element with the lowest frequency among the top k, acting as the threshold to beat. | Distractor Failure: Choosing A fails because the root is the first candidate to be evicted if a higher-frequency element arrives, not the strongest candidate. |
| 11 | **A** - Each list is already sorted, so only its head can be the next global value | Proof and Invariant: Because each source list is already sorted, no later element in a list can be smaller than its current head, so only heads need to compete in the heap. | Distractor Failure: Choosing B fails because if lists were not sorted, you could not guarantee that the absolute minimum resides among the current heads. |
| 12 | **C** - Lower half values are <= upper half values, and heap sizes differ by at most one | Proof and Invariant: Two heaps perfectly balance the lower half (max-heap) and upper half (min-heap) of data, keeping the median accessible at the root(s) in O(1) time. | Distractor Failure: Choosing A fails because if all elements went to one heap, you would lose O(1) access to the middle boundary (the median). |
| 13 | **A** - To prevent immediate adjacent reuse | Proof and Invariant: To prevent adjacent duplicates, the most recently placed character is temporarily held out of the available queue until a different character is placed. | Distractor Failure: Choosing B fails because sorting all characters immediately clumps identical characters together, causing the exact adjacency we must avoid. |
| 14 | **B** - When its next allowed time has arrived | Proof and Invariant: A task in cooldown is temporally blocked; it can only re-enter the available priority queue when the global clock reaches or exceeds its release time. | Distractor Failure: Choosing A fails because tasks do not become available merely when the priority queue is empty; they must wait for their specific cooldown time to elapse. |
| 15 | **A** - The farthest point among the kept closest candidates | Proof and Invariant: For k closest points, a max-heap of size k keeps the farthest of the closest points at the root, making it easy to evict when a closer point is found. | Distractor Failure: Choosing B fails because a min-heap of size k would keep the closest points at the root, making it impossible to quickly find and evict the farthest kept point. |
| 16 | **A** - A heap only guarantees the root priority relationship, not full ordering across siblings | Proof and Invariant: The heap property only enforces that a parent is ordered relative to its direct children; it provides no total ordering among siblings or across subtrees. | Distractor Failure: Choosing B fails because claiming total sorted order would imply binary search trees, whereas a heap array is only partially ordered. |
| 17 | **D** - `O(n log k)` time and `O(k)` space | Proof and Invariant: Tracking top k dynamically limits the heap size to k, ensuring that each of the n insertions takes O(log k) time, resulting in O(n log k) overall. | Distractor Failure: Choosing A fails because O(n log n) implies sorting or pushing all n elements into a full heap, which wastes space and time compared to a size-k bound. |
| 18 | **C** - `O(N log k)` time | Proof and Invariant: A k-way merge keeps exactly k elements in the heap. Processing n total elements involves one push and one pop for each, taking O(n log k) time. | Distractor Failure: Choosing A fails because O(k log n) implies the heap size is n and we only process k elements, which is the inverse of the k-way merge constraints. |
| 19 | **A** - Whether any tied answer is acceptable or deterministic order is required | Proof and Invariant: When priority scores tie, multiple valid groupings can exist; a deterministic output requires enforcing a secondary sort key (like lexicographical order). | Distractor Failure: Choosing B fails because ties do not cause infinite loops; they only cause non-deterministic popping order if the tie-breaker is undefined. |
| 20 | **B** - Squared distance preserves ordering and is cheaper | Proof and Invariant: Calculating squared distance avoids floating-point operations (square roots) while strictly preserving the relative monotonic ordering needed for heap comparisons. | Distractor Failure: Choosing A fails because square roots introduce floating-point precision issues and are computationally more expensive than simple multiplication. |
| 21 | **A** - Some character count exceeds `(n + 1) / 2` | Proof and Invariant: By the pigeonhole principle, if a single character's frequency exceeds (n+1)/2, there are not enough other characters to interleave and separate them. | Distractor Failure: Choosing B fails because the queue size limits the number of unique characters, but it is the absolute majority count that fundamentally breaks interleaving. |
| 22 | **C** - `O(1)` | Proof and Invariant: The two heaps maintain balance such that the median is always strictly at the root of the larger heap, or the average of both roots if sizes are equal. | Distractor Failure: Choosing A fails because reading the median does not require a full O(n) scan; it takes O(1) time precisely because the heaps do the balancing during insertion. |
| 23 | **A** - Negate numeric priorities | Proof and Invariant: In languages without a native max-heap (like Python), negating the numerical priorities perfectly reverses the sort order, simulating a max-heap inside a min-heap. | Distractor Failure: Choosing B fails because creating a custom class is unnecessary overhead when mathematical negation trivially solves numeric priority inversion. |
| 24 | **A** - Letting the heap grow to all `n` items when size `k` is enough | Proof and Invariant: For top-k problems, the heap size should never exceed k. Retaining all elements in memory when only a fraction is needed violates system design bounded-space principles. | Distractor Failure: Choosing B fails because unbound heaps consume O(N) memory, which scales poorly in distributed or streaming environments. |
| 25 | **D** - Merging sorted logs, feeds, or search shard results | Proof and Invariant: Merging continuous streams from multiple shards is directly solved by maintaining a k-way merge heap of the frontier records from each shard. | Distractor Failure: Choosing A fails because loading all streams entirely into a single node's memory (O(N) space) is impossible for infinite or massive feeds. |
| 26 | **A** - Heavy hitters such as top error codes or hottest endpoints | Proof and Invariant: Top-k and heavy hitters (most frequent items) are standard observability queries for identifying abuse, hot partitions, or popular trends in logs. | Distractor Failure: Choosing B fails because consistent hashing focuses on request routing and load balancing, not on querying the most frequent keys. |
| 27 | **C** - Starvation of lower-priority work | Proof and Invariant: A strict priority queue processes highest priority first; without fairness constraints or aging, a continuous influx of high-priority work will permanently starve low-priority items. | Distractor Failure: Choosing A fails because priority queues do not guarantee fairness; they actively bypass older low-priority items in favor of newer high-priority ones. |
| 28 | **A** - Queue age, deadline misses, and starvation rate | Proof and Invariant: Validating a scheduler requires monitoring metrics that reveal degradation: queue delay (age), starvation counters, and deadline misses. | Distractor Failure: Choosing B fails because CPU temperature is an infrastructure metric, not a software metric indicating logical scheduling starvation or fairness. |
| 29 | **B** - Merge local candidates with a second-stage heap or reducer | Proof and Invariant: In a distributed system, individual nodes calculate local top-k candidates, which are then merged via a reducer (another k-way heap merge) for the global top-k. | Distractor Failure: Choosing A fails because sending all raw logs to one central heap node creates a massive network and CPU bottleneck. |
| 30 | **A** - The stream is too large to store exact counts for every key | Proof and Invariant: When exact per-key tracking exceeds memory bounds (e.g., massive distinct streams), probabilistic structures like Count-Min Sketch approximate frequencies to feed top-k heaps. | Distractor Failure: Choosing B fails because exact algorithms using HashMaps require O(N) memory for unique keys, which crashes on internet-scale high-cardinality streams. |
| 31 | **D** - "The heap stores the active frontier, and its size bound gives the `log k` factor." | Proof and Invariant: A strong heap design explicitly states what invariant the heap maintains (the frontier) and its exact maximum size, which dictates both time and space complexity. | Distractor Failure: Choosing A fails because omitting the heap size leaves the space complexity ambiguous and fails to demonstrate bounded-memory design. |
| 32 | **A** - Consider lazy deletion, an indexed heap, or a different ordered structure | Proof and Invariant: Standard heaps do not support fast arbitrary value updates; modifying an existing element requires an external index map or pushing a stale tombstone to be handled later. | Distractor Failure: Choosing B fails because arbitrary search in a heap takes O(N) time, completely destroying the O(log N) performance expectation of priority queues. |

## Written Drill Key

| Drill | Strong answer signal |
|---|---|
| A | The heap contains the `k` largest values seen so far; the root is the kth largest once size is `k`. |
| B | Each sorted source can only contribute its current head next; after popping it, push that source's next item. |
| C | Lower values are <= upper values, and sizes differ by at most one. |
| D | If a character appears more than `(n + 1) / 2`, there are not enough other characters to separate all copies. |
| E | Heap is `O(n log k)` and stream-friendly; quickselect is average `O(n)` for batch selection but mutates or partitions input. |
| F | Track queue age, deadline misses, starvation, retry rate, and rollback or fairness guardrail behavior. |
