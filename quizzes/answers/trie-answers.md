# Trie Quiz Answers

| Question | Answer | State Invariant | Explanation | Distractor Failure |
|---:|---|---|---|---|
| 1 | A | The hierarchical structure cleanly merges shared character prefixes to accelerate O(L) multi-query edge traversal. | Tries are strongest when many queries reuse prefix structure. | Option B ('One pass over a sorted array') fails because a sorted array requires binary searching every prefix, completely missing the `O(L)` edge traversal speed of a Trie. |
| 2 | B | The hierarchy strictly isolates the terminal boolean flags to differentiate whole words from structural prefixes. | Children encode next characters; terminal markers distinguish words from prefixes. | Option A ('Only the full dictionary') fails because standard dictionaries map full exact words natively but cannot easily isolate or aggregate shared partial character prefixes. |
| 3 | C | The node explicitly maintains its transitional status to support longer valid dictionary prefix chains. | The path for `app` exists, but the `app` node is not terminal. | Option A ('Both must be false') fails because a node can exist as a valid transitional prefix for longer words without being flagged as a terminal word itself. |
| 4 | D | The node accurately tracks the multi-child array boundaries to enable simultaneous positional wildcard branching. | Dot wildcard search branches over trie children at wildcard positions. | Option A ('Kth largest element') fails because maintaining a heap for the kth largest element does not enable branching across multiple unknown character wildcard children. |
| 5 | A | The structure cleanly bounds the shortest terminal marker to eagerly halt replacement path traversal. | The first terminal node on the path is the shortest matching root. | Option B ('It is always the longest word') fails because finding the longest word aggressively skips over valid earlier terminal markers, violating the requirement to replace at the shortest root. |
| 6 | B | The hierarchy explicitly propagates the numeric aggregate deltas to correctly maintain parent chain weights. | Overwrites need the delta between old and new values. | Option A ('A queue of visited nodes only') fails because tracking visited nodes in a queue does not solve how to propagate and update numeric aggregate deltas up the parent chain. |
| 7 | C | The prefix boundary strictly bounds the valid character sequence to aggressively prune impossible board paths. | Trie prefix failure stops impossible board DFS branches. | Option A ('Computes shortest paths between cells') fails because computing shortest paths evaluates routing distances, whereas board search needs strict parent-to-child string prefix validation. |
| 8 | D | The structure precisely isolates the candidate suggestion subset to enable rapid bounded autocomplete lookups. | Prefix lookup finds candidates; ranking chooses useful suggestions. | Option A ('Only exact membership') fails because autocomplete systems must match partial user inputs to a prefix node, not just test the database for exact predefined strings. |
| 9 | A | The hierarchy intentionally utilizes directed character edges to explicitly map sequence constraints, unlike undirected components. | Every root-to-node path represents a prefix. | Option B ('A connected component') fails because generic connected components track undirected equivalence classes, completely lacking the directed character-edge hierarchy of a Trie. |
| 10 | B | The structure firmly evaluates the final node terminal state to strictly validate exact dictionary matches. | Exact search requires the final node to be marked as a word. | Option A ('Whenever the path exists') fails because just because a path exists does not mean the characters form a complete valid dictionary word without a terminal marker. |
| 11 | C | The node explicitly maps the fixed character key to traverse exactly one deterministic edge branch. | Fixed characters follow exactly one matching edge. | Option A ('Try every child') fails because a specific fixed character dictates following exactly one deterministic edge, eliminating the need to explore all sibling children. |
| 12 | D | The structure dynamically evaluates all active child pointers to consume exactly one positional wildcard character. | Dot matches one character, so each child is one possible branch. | Option A ('Skip any number of characters') fails because a dot wildcard consumes exactly one string position by testing all immediate children; it cannot arbitrarily skip varying depths. |
| 13 | A | The prefix boundary accurately maintains the aggregate historical values to capture all underlying child keys. | Prefix nodes store aggregate values for keys beneath them. | Option B ('Only the last inserted key') fails because caching only the most recent key overwrites historical data, whereas prefix aggregation requires combining values from all children. |
| 14 | B | The hierarchy strictly isolates the terminal word storage to natively simplify output string deduplication. | Terminal word storage simplifies output and deduplication. | Option A ('To compare graph roots') fails because graph roots define disjoint set components, not the explicit word boundaries needed for string deduplication and output. |
| 15 | C | The structure correctly bounds the dictionary validation check to reject incomplete transitional intermediate characters. | Every prefix of a buildable word must be a word. | Option A ('Every child node, terminal or not') fails because treating every child node as a word incorrectly emits transitional intermediate characters that are not actually in the dictionary. |
| 16 | D | The node strictly identifies single-child sequence chains to safely collapse them via path compression. | Compression reduces long chains where nodes have one child. | Option A ('Connectivity queries') fails because connectivity queries answer whether undirected nodes link together, which is unrelated to collapsing single-child prefix chains. |
| 17 | A | The structure rigidly consumes the sequential character inputs to enforce exact order prefix containment. | Each character is consumed once. | Option B ('`O(log n)` regardless of word length') fails because a valid prefix search must consume all characters in the exact order provided, not just the first one. |
| 18 | B | The hierarchy accurately tracks the allocated child pointers to manage the heavy inherent memory footprint. | Shared prefixes reduce nodes, but child representation still costs memory. | Option A ('Number of queries only') fails because even with shared prefixes, memory is heavily consumed by the array or map pointers required to represent the child edges. |
| 19 | C | The node dynamically fans out the wildcard character searches to explore multiple concurrent valid branches. | Wildcards can explore many child branches. | Option A ('Fixed characters cannot be searched') fails because wildcards force the search algorithm to branch and explore multiple valid character children simultaneously, breaking constant-time determinism. |
| 20 | D | The structure strictly identifies the first matching terminal prefix to perform correct dictionary shortest-root replacements. | Replace Words requires the shortest matching root. | Option A ('Using a terminal marker') fails because replacing words relies on halting at the first terminal prefix match in the tree, not reordering the entire dictionary. |
| 21 | A | The hierarchy precisely calculates the value subtraction delta to properly update overlapping prefix weights. | Overwrite handling must subtract the previous value via delta. | Option B ('Returning zero for missing prefix') fails because if a weight changes, you must specifically calculate the numerical delta and apply it to parents, not just return zero. |
| 22 | B | The structure independently evaluates the multi-path terminal hits to gracefully handle duplicate board grid letters. | Multiple board paths can find the same terminal word. | Option A ('Reusing the same cell') fails because independent valid board traversals can weave through identical character sequences if the grid natively contains duplicate letters. |
| 23 | C | The hierarchy strictly binds the parent-to-child sequential edges to correctly model fixed character alphabets. | Fixed arrays assume a small known alphabet. | Option A ('The graph is undirected') fails because undirected graphs lack the strict parent-to-child sequence necessary to validate strings character-by-character. |
| 24 | D | The node explicitly maps the compact sorted array pointers to optimize modest constrained prefix workloads. | Sorted arrays can be simpler and more compact for modest prefix workloads. | Option A ('When wildcard branching is required on every query') fails because wildcard branching on every query causes severe exponential fan-out, heavily degrading performance if not tightly constrained. |
| 25 | A | The structure efficiently aggregates the autocomplete string candidates to rapidly serve prefix-indexed workloads. | Autocomplete and command lookup are prefix-indexed workloads. | Option B ('Payment idempotency only') fails because payment idempotency enforces exact-match transaction deduplication, which does not utilize hierarchical prefix discovery. |
| 26 | B | The hierarchy strictly bounds the suggestion traversal latency to support production-scale autocomplete ranking guardrails. | Production autocomplete also needs ranking and operational guardrails. | Option A ('Only recursion') fails because production autocomplete ranking relies heavily on usage heuristics and latency bounds, not just recursive tree traversal. |
| 27 | C | The prefix boundary strictly evaluates the structural string existence, leaving full semantic relevance to external algorithms. | Full-text relevance is more than prefix existence. | Option A ('Prefix lookup is impossible') fails because prefix lookup retrieves candidates, but full relevance requires semantic scoring algorithms that evaluate far beyond simple structure. |
| 28 | D | The structure intentionally exposes the suggestion selection rate to accurately gauge user-visible autocomplete quality. | Suggestion selection rate indicates user-visible quality. | Option A ('Number of parent pointers compressed') fails because compressing parent pointers is an internal optimization that does not reflect whether users find the suggestions contextually relevant. |
| 29 | A | The hierarchy explicitly limits the cached string candidates to severely restrict massive duplicate memory bloat. | Caching candidates at every prefix can duplicate large amounts of metadata. | Option B ('No queries can be answered') fails because caching full lists of strings at every prefix node duplicates massive amounts of memory, especially for long dictionary words. |
| 30 | B | The structure actively tracks the bounded prefix freshness to optimize high-velocity hot search paths. | Hot prefixes benefit from bounded precomputation and freshness tracking. | Option A ('Scan every term on every keystroke forever') fails because scanning the full raw dataset repeatedly on every keystroke causes latency spikes that render live autocomplete unusable. |
| 31 | C | The node dynamically maps the sparse child representations to safely handle massive Unicode character alphabets. | Unicode requires explicit normalization and child representation choices. | Option A ('Unicode always fits in 26 children') fails because Unicode supports a massive, sparse character space that completely breaks the memory efficiency of a fixed 26-child array node. |
| 32 | D | The hierarchy accurately balances the metadata update semantics to maintain strict production memory capacity limits. | Strong answers define metadata, semantics, and memory trade-offs. | Option A ('Always sort all words first') fails because sorting all words does not address the strict memory capacity limits and dynamic update semantics demanded by production systems. |


## Written Drill Key

| Drill | Strong answer signal |
|---|---|
| A | `startsWith` only needs the prefix path; `search` also needs a terminal marker. |
| B | Fixed letters follow one child; `.` tries all children for exactly one position. |
| C | Store old key value, apply `new - old` to every prefix node, and update the key map. |
| D | Board DFS stops as soon as the current path is not a dictionary prefix. |
| E | Use prefix nodes with capped top-k suggestions, update on writes, and track freshness and quality metrics. |
| F | Prefix lookup gives fast candidate narrowing; production still needs ranking, memory bounds, abuse controls, and observability. |
