# Dynamic Programming Quiz Answers

| Question | Answer | Why correct | Why an alternative fails |
|---:|---|---|---|
| 1 | A | DP applies strictly when a problem has overlapping subproblems (recalculating the same states) and optimal substructure (global optimum is built from local optimums). If a problem only has optimal substructure but no overlapping subproblems, divide-and-conquer (like Merge Sort) is sufficient. The presence of both is the absolute prerequisite for memoization or tabulation. | Option D (generate every permutation) implies backtracking, which explores all branches without the merging of overlapping subproblems. It solves combinatorial generation, not optimization, and results in factorial time complexity rather than polynomial DP time. |
| 2 | B | The state definition (e.g., "dp[i] is the max profit ending at day i") anchors the entire mathematical recurrence. Without it, transitions cannot be formulated correctly because the semantic meaning of the values being combined is ambiguous. Defining the state is always the mandatory first step of DP design. | Option A (variable names) is purely superficial; calling an array `memo` does not define what its indices mathematically represent. The conceptual mapping of the index to the problem space is what actually matters, not the literal variable token. |
| 3 | C | Sequence DP typically operates on one or more arrays/strings, comparing prefixes or suffixes. "Longest common subsequence" perfectly fits this prefix-matching pattern. The state usually tracks indices of the sequences, deciding whether to include, exclude, or match characters to optimize the global sequence metric. | Option A ("level order") strongly signals a tree or graph BFS, completely unrelated to sequence combinations. It explores structural node layers rather than iterating over string prefixes and suffix matches. |
| 4 | D | A 2D grid with restricted directional moves (right/down) guarantees a DAG structure for paths, perfectly mapping to state transitions of `dp[r][c] = dp[r-1][c] + dp[r][c-1]`. The lack of upward or leftward movement strictly prevents cycles, allowing us to safely define the current cell's value based entirely on previously computed adjacent cells. | Option A ("shortest unweighted path") lacks directional constraints and requires BFS to prevent infinite loops. If all four directions are allowed, DP cannot be directly applied without introducing cycles that break the bottom-up mathematical recurrence. |
| 5 | B | In non-canonical coin systems (e.g., coins 1, 3, 4 and target 6), a greedy choice takes 4, leaving 2 (needs two 1s, total 3 coins). DP explores all paths and finds 3+3 (2 coins). DP guarantees optimality by evaluating the global cost of every valid subpath, effectively avoiding the local optimum trap that ensnares the greedy approach. | Option A (coins are sorted) is often a prerequisite step, but sorting doesn't fix the mathematical flaw in the greedy local choice. Even with sorted coins, greedy will still stubbornly pick the largest denomination first and fail on non-canonical sets. |
| 6 | C | A subsequence maintains relative order but can delete intermediate elements (e.g., 'ace' from 'abcde'). A substring must be strictly contiguous (e.g., 'bcd'). This distinction completely alters the DP state space: substrings require adjacent matching, while subsequences allow state transitions that "skip" non-matching characters. | Option A (subsequence sorted) is false; subsequences strictly preserve the original array's order, which might be entirely unsorted. Sorting the input would fundamentally destroy the original sequence geometry the problem requires analyzing. |
| 7 | D | Word Break asks "Can this string be segmented into dictionary words?", which is a boolean True/False feasibility question, not an optimization min/max value problem. The DP state evaluates to a boolean denoting if the prefix can be segmented, transitioning by checking if any valid previous segment point connects to a valid dictionary word ending here. | Option A (minimum cost) would apply if dictionary words had varying costs and we wanted the cheapest segmentation. However, standard Word Break only asks if any valid segmentation exists at all, strictly yielding a boolean outcome. |
| 8 | B | The 0/1 Knapsack problem maps perfectly to system design constraints: allocating a fixed budget (weight capacity) across components to maximize overall system throughput (value). It formally defines the mathematical tradeoff when you have limited resources and disparate items that yield different returns, closely mirroring CPU/Memory allocations. | Option D (shell command) is an isolated execution step with no overlapping decision trees or combinatorial optimization. Running a command is a singular action, entirely detached from resource capacity planning. |
| 9 | A | The definition `dp[i] = ways to reach step i` allows the recurrence `dp[i] = dp[i-1] + dp[i-2]` to seamlessly aggregate the valid step combinations from previous positions. Since reaching step `i` strictly requires arriving from either `i-1` or `i-2`, the total distinct ways is simply the sum of the ways to reach those two predecessor states. | Option B (house value) belongs to the House Robber problem, which is an optimization (max profit) problem, not a combinatorics (counting ways) problem. Mixing up optimization logic with combination counting completely breaks the state intent. |
| 10 | D | The core DP transition is `max(dp[i-1], dp[i-2] + nums[i])`, representing the binary choice to either skip the current house or rob it (adding its value to the state two houses ago). This brilliantly enforces the non-adjacent constraint while guaranteeing the maximum accumulated wealth at every prefix step `i`. | Option B (left or right pointer) implies a greedy Two Pointer approach, which fails to track non-contiguous sums accurately. Pointers work for sorted arrays or sliding windows, but not for disjoint sequence optimization. |
| 11 | B | Using `infinity` (or `sys.maxsize`) for impossible states ensures that any `min()` operation strictly ignores them. Using 0 would incorrectly treat impossible states as free operations. In minimization problems (like Coin Change), an invalid path must mathematically disqualify itself, and infinity perfectly achieves this. | Option A (zero) ruins optimization because `min(valid_path_cost, 0)` will always wrongly choose the impossible path. This pollutes the DP table with false zeroes, causing the final answer to be wildly incorrect. |
| 12 | C | To extend an increasing sequence, we must know the exact value it currently ends on. `dp[i]` tracking the LIS ending strictly at `i` provides this definitive anchor value. By enforcing that `nums[i]` is the absolute tail of the subsequence, we can safely compare it to previous elements to determine if extension is mathematically valid. | Option A (LIS anywhere) breaks the recurrence because we wouldn't know if `nums[i]` is strictly greater than the last element of that unspecified subsequence. Ambiguous tails prevent deterministic greater-than comparisons. |
| 13 | D | The prefix matching structure allows the state `dp[i][j]` to encapsulate the subproblem of matching the first `i` characters of `text1` with the first `j` characters of `text2`. This 2D coordinate system systematically evaluates every possible prefix combination, ensuring that overlapping matches are mathematically isolated and merged. | Option A (shortest path) implies a 2D grid traversal for spatial pathfinding, which doesn't model character matching logic. String characters do not represent physical grid constraints or movement weights. |
| 14 | B | When `text1[i-1] == text2[j-1]`, both characters confidently extend the best LCS of the prefixes excluding them, pulling the value from the diagonal `dp[i-1][j-1]` and adding 1. The match proves that this character contributes exactly 1 to the sequence length, safely building upon the optimal match of the remaining prefix portions. | Option A (`dp[i+1][j+1]`) is mathematically invalid in bottom-up DP because it looks at future states that haven't been computed yet. Tabulation strictly relies on drawing data from smaller, already solved subproblems. |
| 15 | C | The base case `dp[0]` represents an empty string prefix. An empty string requires exactly 0 dictionary words to be validly segmented, making it trivially `True`. Setting this foundation allows the first actual character matches in the string to look back and validate that they connect to a structurally sound start point. | Option A (impossible) would cause all subsequent valid dictionary matches starting from index 0 to wrongly evaluate to `False`. If the root of the DP tree is false, no valid segmentations can ever be built upon it. |
| 16 | D | Because movement is strictly restricted to 'down' and 'right', a cell `(r, c)` can only be reached from the cell directly above it `(r-1, c)` or directly to its left `(r, c-1)`. This rigid restriction defines the exact two dependencies for calculating the total paths to the current coordinate, perfectly framing the recurrence relation. | Option B (diagonal) applies to sequence DP like LCS or Edit Distance, not orthogonal grid path counting. There are no diagonal moves permitted in standard unique paths algorithms. |
| 17 | B | DP systematically evaluates every unique state exactly once. Thus, Total Time = (Number of Distinct States) * (Time to compute transition for one state). This formula definitively proves why memoizing a recursive function drops its complexity from exponential down to polynomial, directly correlating to the table size. | Option C (`O(1)`) is impossible for DP, as it inherently requires iterating over a dynamically scaling state space `O(N)`. Optimization problems of this nature mathematically require examining the input variables. |
| 18 | C | Top-down DP inherently requires a memoization structure (hash map/array) to store results, plus implicit call stack frames proportional to the maximum recursion depth. Even if the hash map is small, a deep graph of dependencies will push thousands of stack frames, risking StackOverflow on large inputs. | Option A (final answer) dangerously ignores the `O(N)` hidden memory footprint of the recursive call stack. Failing to account for stack memory leads to production crashes under heavy recursive load. |
| 19 | D | If the inner loop iterates forward in 1D Knapsack, it might overwrite `dp[j - weight]` with a value from the *current* item, incorrectly reusing the item. Backward iteration strictly prevents this by ensuring we only read capacities that haven't yet been processed for the current item, perfectly simulating the 0/1 (use once) constraint. | Option B (sorted input) does not inherently prevent state corruption if the array traversal direction is logically flawed. Sorting items by weight does not fix the mathematical violation of reusing the same item twice. |
| 20 | B | To mathematically build up the minimum coins, we start with the absolute truth: it takes exactly 0 coins to make an amount of 0. `dp[0] = 0` anchors the additive logic. Without this zero anchor, the entire sequence of `+1` coin additions has no starting point to build from, rendering the optimization impossible. | Option A (infinity) destroys the base case; any path relying on 0 would inherit infinity, resulting in no valid solutions. Treating the 0 target as impossible completely breaks the foundation of the state transitions. |
| 21 | C | To reach step 0 requires no movement, which represents exactly 1 valid way (do nothing). This ensures `dp[2] = dp[1] + dp[0]` calculates as `1 + 1 = 2`. Philosophically, the "empty set" of actions is a single valid combination, and this mathematical truth anchors the entire Fibonacci-like recurrence sequence. | Option A (zero ways) breaks the additive chain, causing valid combinations relying on the base step to evaluate to 0. If `dp[0]` is 0, then step 2 would incorrectly evaluate to 1 way instead of 2. |
| 22 | D | Because `dp[i]` strictly enforces the sequence ending at `i`, the longest sequence might have terminated earlier if the array ends with small, unusable numbers. Thus, we must iterate through the entire `dp` array and find the maximum value, as the global optimum could be hidden anywhere inside the state space. | Option C (last index best) assumes the array is strictly increasing, which trivially defeats the purpose of the LIS problem. A small final element will inherently have a small LIS ending at its index. |
| 23 | B | LCS compares two strings. For strings of length `m` and `n`, every prefix length of `text1` must be compared against every prefix length of `text2`, forming an `m x n` table. The 2D state space is necessary because characters might match at completely disjoint indices, requiring cross-comparison across both full dimensions. | Option D (`O(m + n)`) would only suffice for a linear Two Pointer scan, which cannot solve non-contiguous LCS properly. Two pointers fail to backtrack and explore overlapping skipped characters in disjoint sequences. |
| 24 | C | Directly jumping to 1D compression obscures the state dependencies and introduces indexing bugs. Writing the 2D logic first proves the transitions are mathematically sound. Once the uncompressed 2D matrix accurately solves the recurrence, optimizing it to 1D by analyzing the row dependencies is a safe, mechanical step. | Option B (use greedy) abandons the correct algorithm entirely, failing the optimization requirement. Switching to a greedy approach when overlapping subproblems exist guarantees an incorrect global outcome. |
| 25 | D | DP provides a formal framework for optimizing decisions across stages (states) under strict limits (constraints), mapping perfectly to system capacity planning and budget allocation. Whether routing network packets or provisioning server load, DP mathematically models the trade-offs of finite resources to maximize a global utility metric. | Option C (renames APIs) is a purely superficial coding task devoid of algorithmic or systemic trade-off analysis. Refactoring names has no impact on system capacity or mathematical optimization. |
| 26 | B | If a DP memoization key drops a constraint (e.g., `(index)` instead of `(index, capacity)`), it returns invalid cached data. This perfectly mirrors production cache collisions from weak keys. In both cases, failing to include all variance in the key leads to serving stale or contextually incorrect data to the consumer. | Option C (lower latency) might occur, but serving corrupted/incorrect data renders the latency irrelevant. A fast system that returns the wrong answer is functionally broken and useless. |
| 27 | C | In DP, sentinels (infinity) naturally prune invalid paths. In systems, failure states must be explicitly typed and handled, not zeroed out, to trigger correct retry/fallback logic. Masking an error with a zero or null value destroys the telemetry needed to gracefully recover from the fault or trigger circuit breakers. | Option A (ignore invalid states) can lead to silent data corruption or masking of critical upstream errors. In both DP and systems, invalid states must be mathematically or logically excluded, not silently assimilated. |
| 28 | D | A formal DP contract defines exactly what is tracked (State), how it changes (Transition), the goal (Objective), and the limits (Constraints). This models pipeline bottlenecks perfectly. By rigidly defining these parameters, engineers can objectively evaluate where the system is bound and what trade-offs yield the highest throughput. | Option A (recursion depth) is merely an execution detail, not a structural modeling framework for optimization. It tells you about memory pressure, but nothing about the mathematical constraints of the problem domain. |
| 29 | B | The recurrence is the mathematical heart of DP. Explaining it proves the candidate understands *why* the code works, distinguishing true engineering from memorized cargo-culting. If a candidate can articulate the transition formula, they demonstrate the ability to adapt the logic to novel constraints and variants. | Option D (removes base cases) is false; a correct recurrence still strictly requires base cases to terminate and anchor logic. Removing base cases would cause infinite loops or out-of-bounds index errors. |
| 30 | C | Greedy algorithms are faster but unsafe unless the problem exhibits the greedy-choice property. A candidate must mathematically justify that the local optimum never traps the global path. Without this formal proof, greedy approaches are simply hopeful heuristics that will inevitably fail on specific edge cases (like non-canonical coin sets). | Option B (values are positive) is a constraint for Dijkstra's, not a universal proof for the validity of greedy over DP. Positive values do not inherently guarantee that early local choices won't eliminate better long-term paths. |
| 31 | D | A complete DP summary formally states the definition of the state, the transition recurrence, base cases, traversal order (e.g., bottom-up), and `O(States * Cost)` complexity. This exhaustive breakdown guarantees that every structural pillar of the algorithmic solution is explicitly addressed and logically sound. | Option A (used an array) is completely trivial and fails to explain the underlying logic of the dynamic programming model. Anyone can instantiate an array; true engineering lies in defining what the array's cells mathematically represent. |
| 32 | A | When state space exceeds memory limits, an engineer must architect practical fallbacks: compressing dimensions, pruning dead branches, or using sparse HashMaps instead of dense arrays. This demonstrates senior-level pragmatism, acknowledging that textbook `O(N^2)` memory isn't always viable in constrained production environments. | Option D (increase recursion) will just cause a deeper StackOverflow, failing to address the fundamental memory exhaustion. Throwing more stack frames at an out-of-memory error fundamentally misunderstands the bottleneck. |
