# BFS / DFS Quiz Answers

| Question | Answer | Why correct | Why an alternative fails |
|---:|---|---|---|
| 1 | B | BFS expands radially level-by-level, ensuring the first time a node is reached it is via the minimum number of unweighted edges. This level-order traversal perfectly maps to shortest paths where all edge weights are identical. By processing all distance `d` nodes before any distance `d+1` nodes, we guarantee optimality. | Option A (permutations) requires exploring all complete paths and backtracking, not layer-by-layer expansion. Backtracking is inherently a depth-first search approach, which dives deep into a single branch rather than expanding uniformly across the state space. |
| 2 | A | DFS naturally tracks the active path in a call stack or explicit stack, allowing it to easily spot back-edges to 'visiting' nodes which strictly denote cycles. The depth-first approach explores as far as possible along each branch before backtracking, making it ideal for topological sorting and cycle detection. | Option D (first position in a sorted array) is solved with binary search in `O(log n)` time. It does not involve `O(V+E)` graph traversal, as there are no vertices or edges to explore in a hierarchical graph structure. |
| 3 | C | In the matrix representation of a grid graph for connected components, the "1"s (land cells) act as the vertices/nodes that can be connected to adjacent "1"s (the edges). This forms a clear undirected graph model where islands are connected components of land vertices. Traversing from one land cell to its neighbors discovers the entire island. | Option A (water cells) are boundaries or empty space, not the entities we are trying to group into islands. Treating water as vertices would compute the connected components of the ocean instead, missing the primary objective of grouping landmasses. |
| 4 | D | "Simultaneous spread" directly models adding multiple initial nodes to the BFS queue at layer 0, expanding them uniformly outward level by level. This multi-source BFS pattern accurately mimics real-world phenomena like fire spreading, disease transmission, or rotting fruit. All initial sources are enqueued before the traversal begins. | Option A ("all subsets") indicates backtracking or bitmasking to generate powersets, not distance-based spreading. Generating subsets is an exponential time combinatorial problem, whereas spreading is a linear time topological expansion. |
| 5 | B | BFS assumes all edges cost 1 unit of distance; weighted graphs require Dijkstra's or Bellman-Ford to correctly minimize total weight instead of edge count. When edge weights differ, the number of edges on a path no longer correlates directly with the total path cost. BFS might find a path with fewer edges that is actually much more expensive overall. | Option D (unit moves in a grid) is exactly the unweighted scenario where BFS optimally finds shortest paths. Moving to any adjacent cell costs a constant 1 unit, perfectly aligning with BFS's uniform expansion invariant. |
| 6 | C | Topological sort requires a Directed Acyclic Graph (DAG) because any directed cycle creates an impossible dependency loop where neither task can precede the other. If task A depends on task B and task B depends on task A, no linear ordering can satisfy both constraints. Thus, cycle-freedom is a strict mathematical prerequisite. | Option A (undirected tree) naturally lacks directed dependency constraints, making topological ordering meaningless. Without directionality on the edges, there is no concept of a task needing to finish before another can begin. |
| 7 | A | Starting BFS/DFS from the ocean borders inward identifies all reachable cells in a single pass, rather than launching a redundant `O(V+E)` search from every individual land cell. This reverse-reachability technique drastically prunes the search space by starting from the global targets (the oceans) rather than the numerous local sources. | Option C (House Robber) is a 1D Dynamic Programming sequence optimization problem, not a spatial graph traversal problem. It focuses on maximizing a sum over an array under adjacency constraints, completely disconnected from pathfinding or reachability. |
| 8 | D | Web crawlers fundamentally operate like BFS: they maintain a frontier (queue) of unvisited URLs (neighbors) and expand outward to crawl the web layer by layer. This ensures that the crawler discovers the most closely linked pages first, mapping the internet's structure in a breadth-first manner. A queue seamlessly manages the backlog of links. | Option B (memo table compression) relies on 1D/2D array pointer manipulation in DP space reduction, not graph traversal. It is an memory optimization technique for state tables, utterly unrelated to discovering structural graph connections. |
| 9 | B | Marking nodes as visited exactly when they are added to the queue prevents multiple paths from enqueuing the same node, maintaining a bounded queue size and avoiding duplicate work. If deferred until popping, a node with high in-degree might be enqueued multiple times from different neighbors. Early marking is critical for `O(V+E)` time bounds. | Option A (sorting neighbors) is irrelevant to basic BFS correctness and typically only needed if a strict lexicographical tie-breaking order is required. Sorting does not prevent duplicate processing or infinite loops. |
| 10 | C | The 'visiting' state (often gray) signifies the node is currently in the recursion stack; encountering it again means we've found a back-edge, proving a cycle. It is a critical tri-color marking state that distinguishes a true cycle from a harmless cross-edge to an already fully processed subtree. | Option A (fully processed/black) means all descendants are explored and safe, so linking to it does not form a cycle. Pointing to a black node simply means we are referencing an already validated, cycle-free subset of the graph. |
| 11 | D | Capturing `size = queue.length` before the loop ensures we only pop the nodes belonging to the current depth level, cleanly separating distance tiers. Since BFS dynamically enqueues new neighbors, reading the size statically at the start of the level prevents the loop from bleeding into the next layer's nodes. | Option B (detect cycles) is handled by the visited set tracking, not the queue size grouping mechanism. A visited set identifies previously seen nodes, while level-size capturing merely organizes the processing batches. |
| 12 | A | The map ties the original node reference to the new clone reference; without it, traversing shared neighbors would create redundant duplicates or infinite loops on cycles. It acts as both the visited set and the registry for linking edges between newly created clone nodes. This ensures structural parity between the original and clone graphs. | Option D (convert graph to tree) is incorrect because cloning must perfectly preserve the original graph's exact structure, including any cycles and back-edges. We are not flattening the data structure into a hierarchical tree. |
| 13 | B | The word mutations form an unweighted graph where each valid 1-letter change is an edge; BFS guarantees the first path found is the shortest transformation sequence. Since all mutations carry equal weight, expanding radially from the start word ensures the target word is discovered at the minimum possible depth. | Option A (DFS is shortest) is definitively false; DFS dives deep and might find a very long transformation sequence first before eventually finding shorter ones. It fundamentally lacks the shortest-path invariant on unweighted edges. |
| 14 | B | An edge pointing to a 'visiting' state means a course prerequisite loops back to a course currently being resolved, creating an impossible deadlock cycle. In the context of course scheduling, this means Course A requires Course B which eventually requires Course A. Thus, it's impossible to complete all courses. | Option A (True) ignores the back-edge entirely, missing the critical requirement that DAGs must be strictly cycle-free to yield a valid topological order. Allowing the cycle would result in returning an invalid completion plan. |
| 15 | C | The grid may contain multiple isolated islands (disconnected components); an outer loop is needed to start a new traversal for any unvisited land cell. A single BFS or DFS traversal will only map the connected landmass originating from its start node. Thus, sweeping the whole grid ensures no disconnected subgraph is ignored. | Option D (diagonal cells connected) is a rule variation about how edges are defined, but doesn't explain why a single start point fails to reach isolated components. Even with diagonal movement, disconnected components remain disconnected. |
| 16 | D | Because the water naturally flows downhill to the ocean, the reverse search must travel uphill (height >= current) from the ocean to find valid source cells. We are simulating water flow backwards in time, so any neighbor that is at least as high as the current cell is a valid origin point for the water. | Option A (lower neighbors) would find where water from the ocean flows, not where water can originate from. Since water flows from high to low, traversing to lower neighbors represents downhill movement away from the ocean, which is impossible. |
| 17 | A | BFS and DFS strictly process each vertex once (when marked visited) and examine each edge once (or twice in undirected), yielding linear `O(V + E)` time. This complexity bounds the algorithm's runtime to the size of the graph structure itself. No vertex or edge is processed repeatedly due to the visited set constraints. | Option C (`O(V^2)`) only occurs in dense graphs represented by an adjacency matrix, but standard adjacency lists keep it tightly bound to `O(V + E)`. Assuming `V^2` ignores the common use of sparse graphs. |
| 18 | B | Each of the `R * C` grid cells is added to the queue or recursion stack at most once, resulting in a strictly linear traversal of the 2D array space. At worst, every cell in the grid is land and reachable, meaning the algorithm touches all `R * C` elements exactly once before completion. | Option A (`O(log C)`) implies a binary search partitioning strategy, which cannot explore an entire connected component in a multi-dimensional grid. Binary search scales logarithmically on sorted 1D arrays, not spatial 2D structures. |
| 19 | C | DFS relies on stack frames; in the worst case (e.g., a linked list shaped graph), the recursion stack grows to depth `V`, requiring `O(V)` auxiliary space. Each nested recursive call consumes memory to store local variables and the return address. Even an iterative DFS requires an explicit stack that can grow to size `O(V)`. | Option D (CPU cache only) ignores the algorithmic necessity of tracking the backtracking path in heap or stack memory. The CPU cache handles fast data retrieval, but the language runtime manages the deep call stack allocations. |
| 20 | D | The problem typically asks for the minimum time to rot all oranges; if any fresh oranges remain after the BFS finishes spreading, it's impossible, hence return `-1`. This final check ensures that completely isolated components of fresh oranges are properly identified as unreachable by the rotting spread. | Option B (last queue size) just gives the number of oranges that rotted in the final minute, not the failure condition flag. Returning the queue size completely misses the requirement to flag impossible scenarios. |
| 21 | A | If the input node is null, there is no graph to traverse or clone; the algorithm must immediately return null to avoid null pointer exceptions. This is the canonical base case for deep cloning object graphs. Attempting to access neighbors on a null object will invariably crash the program. | Option D (empty dictionary) applies to string matching problems like Word Break or Word Ladder, not the structural cloning of a given graph node pointer. Node pointers are generally checked for nullity, not emptiness. |
| 22 | B | Word Ladder often asks for the number of words in the path (nodes), which is exactly the number of edges (mutations) plus one. Off-by-one errors here are common when developers mix up counting steps vs counting sequence items. Always verify if the prompt asks for distance or sequence length. | Option D (marking visited) is a core structural requirement of BFS to prevent loops, but the classic bug specific to Word Ladder's distance return value is returning `distance` instead of `distance + 1`. |
| 23 | C | In the worst case (a perfectly balanced tree's bottom level), the BFS queue holds `w` nodes, which is roughly `n/2` or `O(n)` space, not `O(1)`. This is the fundamental trade-off of BFS: it uses significant memory to store the wide frontier. A tree's maximum width dominates the spatial footprint. | Option A (`O(1)` always) is a dangerous misconception; BFS requires substantial auxiliary queue memory proportional to the maximum graph width. True `O(1)` space is extremely rare for graph traversals without destructive pointer manipulation. |
| 24 | D | A massive, snake-like connected component can cause recursive DFS to push tens of thousands of frames, easily exceeding default stack limits and causing a StackOverflow. Modern runtimes often limit the call stack to a few thousand frames. Thus, an explicit stack iteration is often preferred for deep, linear graphs in production. | Option C (`O(log n)` time) is incorrect; DFS always remains `O(V + E)` time regardless of recursion depth. The issue is memory limit exhaustion, not sudden improvements in execution speed. |
| 25 | A | The queue of a web crawler acts exactly like a BFS frontier, popping a URL, fetching its HTML, and appending unvisited links to the back of the queue. This structure ensures that pages closer to the seed are crawled before pages further away. It perfectly emulates level-order expansion on the massive graph of the internet. | Option C (DP table compression) is memory optimization for overlapping subproblems in dynamic programming, completely unrelated to URL discovery. Dynamic programming does not model web page hyperlinking structures. |
| 26 | B | Without a visited set, a graph traversal gets stuck in an infinite loop on cycles; in production, this manifests as redundant task execution or infinite retry storms. A crawler might bounce back and forth between two mutually linked pages forever. The visited set acts as the essential deduplication mechanism to protect system resources. | Option C (lower memory usage) is technically true, but missing the visited set fundamentally breaks algorithmic correctness, making any minor memory savings irrelevant. The process will eventually crash or timeout regardless. |
| 27 | C | CI/CD build pipelines are DAGs; checking for directed cycles ensures we don't define a pipeline where Job A waits for Job B, and Job B waits for Job A. Cycle detection validates the orchestrator's ability to actually run the pipeline. Without it, the system would silently deadlock on circular dependencies. | Option B (Cache TTL tuning) handles time-based eviction of stale data, not structural dependency ordering. It is a completely orthogonal concept to graph cycle detection and task scheduling. |
| 28 | D | In BFS, a node with massive degree (e.g., a super-node) instantly blows up the queue size, mirroring real-world message queue bloat and Out Of Memory (OOM) crashes. Enqueueing millions of neighbors at once demands immense auxiliary memory. This width explosion highlights the spatial vulnerability of unconstrained BFS. | Option A (balanced search) is a tree depth guarantee, completely opposite to the explosive width growth of BFS. Balanced structures attempt to constrain depth, not manage massive fan-out at a single node level. |
| 29 | A | When the branching factor is `b` and distance is `d`, standard BFS touches `O(b^d)` nodes. Bidirectional BFS from both ends meets in the middle, reducing time to `O(b^(d/2))`. This symmetric expansion drastically shrinks the total search area while maintaining optimality. It requires both the start and target nodes to be known upfront. | Option B (coin combinations) is an optimization problem solved by dynamic programming, not a pathfinding search with distinct start/end targets. Bidirectional search applies specifically to reachability queries. |
| 30 | B | Marking nodes 'visiting' lets the orchestrator pre-validate the DAG for cycles before starting jobs, preventing deadlocks during live pipeline execution. This fail-fast validation ensures that erroneous cyclical configurations are rejected immediately. Waiting until runtime to discover a loop causes partial failures and stuck states. | Option C (compresses arrays) refers to 1D DP space optimization, not graph execution logic. The visiting state has nothing to do with compressing memory structures for tabular data. |
| 31 | C | Modifying the input grid (e.g., changing '1' to '0') saves `O(R*C)` visited set space, but is a destructive side effect. One must always ask the interviewer if mutation is permitted. Altering shared inputs can break concurrency contracts and corrupt data for subsequent downstream operations. | Option A (always mutate silently) is a critical engineering anti-pattern that can corrupt shared data structures in production. Silent mutations lead to subtle, hard-to-track bugs when other functions expect the original state. |
| 32 | D | A strong candidate explicitly maps the problem to a graph, justifies the BFS/DFS choice based on shortest-path/connectivity, proves the visited invariant, and derives `O(V+E)`. This comprehensive explanation demonstrates full mastery of both the abstract theory and practical implementation constraints. It hits all evaluation rubrics accurately. | Option A (shorter code) relies on aesthetic preference rather than algorithmic and memory guarantees. Concise code is useless if it selects the wrong traversal strategy or fails to manage spatial complexity bounds. |
