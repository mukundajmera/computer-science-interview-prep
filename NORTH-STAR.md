## B. North Star Statement

### Vision

> **computer-science-interview-prep** is the ultimate open-source system-design
> and GenAI system-design preparation source — a single repository that takes a
> learner from zero to interview-ready across classic distributed systems, modern
> GenAI architectures, and hands-on coding, with an optional learning portal for
> interactive study.

### Target Audience & Outcomes

| Audience | Outcome |
|----------|---------|
| **Mid-level engineers (2-5 YoE)** preparing for system design interviews | Confidently tackle LLD, HLD, and GenAI SD rounds at top-tier companies |
| **Senior / Staff engineers** brushing up on fundamentals | Quick-reference material, deep-dive case studies, and rubrics for self-assessment |
| **Self-learners and bootcamp grads** building distributed-systems intuition | Progressive theory → pattern → project pathway with executable examples |
| **Interviewers and educators** | Reusable rubrics, scoring guides, and practice templates |

### Scope

| In Scope | Description |
|----------|-------------|
| **Classic System Design** | Theory, 23 design patterns, 20 LLD projects, 12 HLD concepts, 8 HLD systems — all with versioned Java & Python code |
| **GenAI System Design** | Concepts (RAG, safety, evaluation, etc.), GenAI LLD components, GenAI HLD case studies |
| **Practice & Evaluation** | Rubrics, timed interview templates, quizzes, flashcards, self-review checklists |
| **Learning Portal** | A lightweight web app (`apps/portal`) that renders repo Markdown as an interactive curriculum with progress tracking |
| **Supporting Resources** | Study plans, cheatsheets, interview tips, comparison tables, case studies |

### Non-Goals

| Non-Goal | Rationale |
|----------|-----------|
| Production-grade frameworks or libraries | This is an educational repo, not a toolkit to ship |
| Heavy external dependencies (LangChain, Spring, Django, etc.) | Keep examples self-contained and standard-library-only |
| Video content or paid tiers | Markdown-first, open, free |
| Language support beyond Java & Python | Two languages provide sufficient parity without maintenance burden |
| Deployment infrastructure (Docker, K8s configs) | Out of scope; learners run code locally |
| LeetCode-style algorithm grinding | `05-coding-problems` is optional supplement, not core mission |

## C. Constraints & Principles

### Content Principles

1. **Markdown-first.** All learning content lives in `.md` files inside this
   repo. The portal reads from these files — no content duplication.
2. **Java + Python parity.** Every code artifact ships in both languages
   (exception: GenAI LLD is Python-first per AGENTS guidance; Java parity is
   a stretch goal).
3. **Progressive versioning.** Solutions follow `v1-basic` → `v2-extended` →
   `v3-optimized` so learners see iterative refinement.
4. **Standard library only.** No external deps for code examples. JUnit 5
   standalone JAR is the sole testing exception for Java.
5. **Interview-oriented.** Every project includes requirements, approach, design
   trade-offs, and (eventually) a scoring rubric.

### Structural Principles

6. **Numbered top-level directories.** `00-` through `06-` define study flow.
   Never renumber without maintainer sign-off.
7. **One AGENTS.md per section.** Localized guidance for agents and contributors;
   deepest scope wins when guidance conflicts.
8. **Diagrams in `diagrams/`.** Mermaid `.mmd` sources only; rendered assets
   regenerated on demand.
9. **Portal lives under `apps/portal/`.** Decoupled from content; imports
   Markdown at build/render time.
10. **Cross-link everything.** Follow `CROSS-REFERENCE-GUIDE.md` patterns when
    adding or updating content.

### Process Principles

11. **Small, scoped PRs.** One logical change per PR; follow commit convention
    (`feat:`, `fix:`, `docs:`, etc.).
12. **Tests required.** Happy-path + edge-case tests for all code changes.
    Clean `.class` files before committing.
13. **Dashboard accuracy.** Update `README.md` status tables, `CONCEPTS.md`, and
    study plans whenever content counts or statuses change.
14. **CI plus local evidence.** GitHub Actions smoke workflows cover stable
    repository and portal gates, but contributors must still run local targeted
    validation and document environment-only blockers.
15. **GenAI content currency.** Quarterly concept reviews and semi-annual HLD
    refreshes to stay current with fast-moving field.
