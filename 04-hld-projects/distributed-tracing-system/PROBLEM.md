# Distributed Tracing System (Jaeger/Zipkin/Dapper)

## Problem Statement

Design a distributed tracing system to monitor and troubleshoot microservices-based applications. The system should collect, store, and visualize trace data to help engineers understand the flow of requests across service boundaries, identify performance bottlenecks, and root cause errors.

### Core Requirements

#### Functional Requirements
1. **Trace Ingestion:** Services should be able to send spans (representing a single operation within a trace) to the tracing system.
2. **Trace Assembly:** The system must assemble individual spans into complete traces based on unique Trace IDs.
3. **Query and Search:** Users must be able to search for traces by Trace ID, Service Name, Operation Name, Tags/Annotations (e.g., error=true), and Time Range.
4. **Visualization:** Provide a UI to visualize the trace as a Gantt chart or DAG (Directed Acyclic Graph) showing timing, relationships, and critical paths.
5. **Sampling:** Support sampling strategies (e.g., head-based or tail-based sampling) to manage the massive volume of tracing data without losing anomalous or error traces.

#### Non-Functional Requirements
1. **High Throughput:** The system must handle millions of spans per second during peak traffic.
2. **Low Latency:** Ingestion should be extremely fast and not impact the performance of the monitored services.
3. **Scalability:** The ingestion and storage layers must scale horizontally.
4. **Reliability:** The tracing infrastructure must be robust. Minor data loss (e.g., losing a few non-error traces) is acceptable, but system availability is paramount.
5. **Data Retention:** Traces should typically be retained for a short period (e.g., 7-14 days) for immediate troubleshooting.

### Typical Interview Constraints
- **Traffic Volume:** 10,000 services, 100K Requests Per Second (RPS) entering the system, average 50 spans per request.
- **Span Size:** Average span size is ~500 bytes.
- **Data Growth:** Unsampled data volume is extremely high; sampling is required.

### Key Challenges
- Managing the sheer volume of data generated by tracing every request.
- Deciding between Head-based Sampling (easy, early decision) vs. Tail-based Sampling (complex, requires buffering, but captures all errors/anomalies).
- Efficiently querying and aggregating traces distributed across multiple storage nodes.
