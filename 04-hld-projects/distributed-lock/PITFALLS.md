# Pitfalls
- GC pauses causing lock expiry.
- Split brain.
- Issuing fencing tokens without validating them at the storage layer: a monotonically increasing token from the Lock Service provides zero safety if the downstream Storage node does not reject writes carrying a token older than the highest token it has seen. Enforce strict monotonic token checks on every mutating storage write.
- Granting locks without a bounded lease TTL: if a client crashes or loses network connectivity while holding an indefinite lock, the resource deadlocks permanently and violates the deadlock-free requirement. Attach a bounded TTL to every lease and renew it via heartbeats only while the holder is healthy.
- Performing non-atomic check-and-delete on lock release: if Client A checks ownership, pauses, lets its lease expire, and then sends a plain delete, it can accidentally unlock Client B's newly acquired lease. Release locks atomically by matching the client's unique owner/token value inside a single compare-and-delete operation.
- Relying on wall-clock timestamps for lease expiration across nodes: NTP jumps or clock skew between clients and lock nodes can expire a lease early or extend it past its bound, breaking mutual exclusion. Base lease tracking on monotonic clocks within a single consensus leader and size TTLs conservatively above worst-case drift.
- Deploying a single-node Lock Service as a single point of failure: an un-replicated lock node violates the fault-tolerance requirement and stalls all callers whenever it restarts. Run the Lock Service on a quorum-based consensus group (such as Raft or Paxos) so lock state survives minority node failures.
- Triggering thundering herds when a contended lock is released: waking every waiting client simultaneously to poll for the lock saturates the Lock Service and increases tail latency. Use bounded exponential backoff with jitter or server-side watch notifications with fair queueing so only the next waiter attempts acquisition.
- Ignoring client lease-extension failures during long critical sections: assuming a background heartbeat thread always succeeds lets a client continue mutating Storage after its lease has silently lapsed. Abort or fence local work immediately if lease renewal fails before the TTL deadline.
